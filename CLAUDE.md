# FreeDesign

Herramienta de taller para diseñar y fabricar prendas personalizadas (outfits para clientes concretos y, más adelante, una marca propia). Apartados: Dashboard, Clientes, Diseñador, Proyectos, Producción, Biblioteca y Economía; se construyen por fases. Incluye una vista previa 3D (maniquí animado con la prenda). Somos dos personas trabajando en paralelo, cada una con su propio Claude, sobre este mismo repositorio.

## Stack

- **Vite + React 19 + TypeScript** (`src/`)
- **Three.js** con **@react-three/fiber** y **@react-three/drei** para el 3D
- **React Router** para las páginas de cada apartado
- **Cloudflare Workers**: sirve la web (static assets) y la API `/api/*` (`worker/index.ts`), configurado en `wrangler.jsonc`
- **Cloudflare D1** (SQLite) para los datos; migraciones en `migrations/`. En local, `npm run dev` arranca web + API + base de datos local (plugin `@cloudflare/vite-plugin`)

## Comandos

- `npm install` — instalar dependencias
- `npm run dev` — aplica las migraciones a la base de datos local y arranca web + API en http://localhost:5173
- `npm run db:migrate:remote` — aplica las migraciones a la base de datos de producción
- `npm run build` — comprobación de tipos (web y API) + build a `dist/`. **Ejecutarlo antes de cada commit**: si falla, no se sube.
- `npm run deploy` — build + `wrangler deploy` (normalmente no hace falta: Cloudflare despliega solo al fusionar en `main`)

## Estructura

### App y datos

- `src/App.tsx` — rutas de cada apartado; `src/layout/AppLayout.tsx` — menú lateral flotante (una tarjeta, con la cuenta abajo; en pantallas estrechas sigue en vertical, solo con iconos)
- Inicio (`/`, `src/pages/StudioHome.tsx` + `home.css`): el probador 3D en un plató de fotos oscuro (`Scene stage="studio"`, decorado en `src/three/PhotoStudio.tsx`: fondo infinito blanco en una nave oscura, flashes con octabox, paraguas y stripbox sobre pies con sacos y cables, V-flat y cajas, texturas hechas en el navegador y revelado con `@react-three/postprocessing` en `StudioEffects`: oclusión ambiental, halo, viñeta y grano) con un outfit al azar hecho con los diseños de la cuenta (prenda de arriba, pantalón y calzado; si aún no hay diseños, prendas base de `src/designer/randomOutfit.ts`) y el menú de cristal oscuro encima. El Dashboard está en `/dashboard`
- Estilo de la app: modo claro con todo flotando (menú de cristal blanco, tarjetas y paneles del editor y del Probador con sombra; ver el final de `styles.css`, `studio-editor.css` y `studio.css`). El plató de fotos es el fondo fijo de toda la app (`src/layout/StudioBackdrop.tsx`, un solo `Scene stage="studio"` detrás de todo): en la portada sale con el maniquí y se puede girar (la portada le pasa lo que lleva con `useStage`); en los apartados queda quieto (`frameloop="demand"`) y sin maniquí, a la vista detrás de los paneles claros flotantes. Lo que va directamente sobre el plató (texto suelto dentro de `.page`) se escribe en claro y lo que tiene fondo claro propio vuelve a la letra oscura (variables `--text`/`--muted` por zonas, al final de `styles.css`); el título de cada apartado (`.page-title`), las pestañas (`.tabs`) y los títulos y notas sueltos van sobre una placa de cristal oscuro para que se lean sobre cualquier zona del plató
- Cuentas: cada usuario (particular o empresa) tiene su espacio privado. `src/auth/AuthContext.tsx` guarda la sesión (`useAuth`) y protege las rutas (`RequireAuth`, `GuestOnly`); pantallas en `src/pages/auth/AuthPages.tsx` (/entrar, /registro) y `src/pages/account/Profile.tsx` (/perfil, también la paleta de colores de la marca: `User.brandColors`, que se guarda aparte con `PUT /api/auth/brand` y sale en el creador de gráficos y en las piezas del Diseñador). Tipos en `src/shared/users.ts`
- `src/pages/` — una página por apartado (`Dashboard.tsx`, `clients/`, `library/`, `designer/`, `projects/`, `production/`, `economy/` y `Sections.tsx` con la página de «no encontrada»)
- Proyectos (`src/pages/projects/`): tablero por fases (arrastrar cambia la fase), lista, ficha (datos, diseños, archivos, materiales y costes, tareas, notas) y colecciones. Fases y categorías de archivo en `src/shared/projects.ts`. Las partes de un proyecto (archivos, materiales, costes, tareas) se guardan al momento con `api.projectPart`; los datos principales con «Guardar cambios»
- Producción (`src/pages/production/`): órdenes de fabricación (muestra o tanda, taller, unidades por talla y pasos que se marcan al terminarlos) y la ficha técnica de cada proyecto (`/produccion/ficha/:id`), con cuatro hojas A4 que se imprimen o guardan como PDF (`@media print` en `production.css`). La ficha se genera del diseño, el cliente y los materiales; solo se guarda lo elegido o retocado (`TechPackData` en `src/shared/production.ts`), y cada guardado sube la versión. `src/production/measurements.ts` calcula las medidas de la prenda (tallaje estándar XS–XXL o a medida, más la holgura de cada corte) y `construction.ts` la confección y el orden de montaje por defecto de cada prenda base
- Economía (`src/pages/economy/`): resumen del año (cobrado, costes de proyectos, gastos generales, beneficio y pendiente de cobro), gráfico mes a mes, rentabilidad por proyecto, cliente y colección, y gastos generales (`/economia/gastos`). Los cobros son una parte más del proyecto (`payments`, en su ficha). Criterio de fechas: ingresos por la fecha del cobro, costes de proyectos por cuándo se apuntaron, gastos generales por su fecha. Tipos en `src/shared/economy.ts`; API en `worker/economy.ts`
- `src/designer/` — Diseñador 2D: dibujos técnicos (flats) paramétricos en SVG. `templates.ts` es el catálogo de prendas base (piezas, opciones y cómo se dibujan); `top.ts` dibuja las prendas de torso (sudadera, camiseta, polo, camisa, bomber, puffer: cuellos `Neck`, tapeta con botones, bajo curvo, puño camisero, canesú, acolchado con canales de varias formas —rectos, en V, ondulados, rombos, cuadros, verticales, diagonales— en `quilt.ts`, recortados a la pieza con `Shape.clip`; con «A mano» no salen y se dibujan con el lápiz marcando «Canal de acolchado», `Drawing.quilt`) y extras de cuello y capucha que se combinan (capucha cruzada, cuello alto bajo la capucha, balaclava y lengüeta del cuello: `hoodExtras`/`neckTab` en `top.ts`, y `withNeckExtras` en `templates.ts` añade sus opciones y piezas a una prenda); `pants.ts` los pantalones (jogger/cargo, ancho, corto: cintura elástica o con trabillas, pinzas, bajo vuelto); `head.ts` los gorros y gorras; cada prenda base tiene `family` (`top`, `pants` o `head`), que decide medidas, cotas, ficha y forma 3D (`isPants`, `isHead`). Las prendas de cabeza se dibujan más grandes: `GarmentTemplate.unitsPerCm` (8 en vez de 2) y `unitsOf(t)` (`prints.tsx`) dan la escala de estampados, detalles, cuadrícula y ficha; `FlatView.tsx` pinta una vista con los colores y materiales de cada pieza (o en «línea», blanco y negro), deja elegir una pieza con un clic y acepta una capa encima (`overlay`). Añadir una prenda base = una entrada en `TEMPLATES` (puede reutilizar `drawTop`, `drawPants` o los de `head.ts`) y en `NEW_DESIGN_CATALOG`, que es lo que sale en «Nuevo diseño» (ahí también van los atajos: una prenda base con otras opciones de partida, p. ej. la camiseta de manga larga o el pantalón de chándal); sus medidas en `garmentPoms` (`measurements.ts`), su confección en `construction.ts` y su material por defecto en `DEFAULTS` (`materials.ts`)
- Editor (`src/pages/designer/DesignEditor.tsx`), tipo estudio: capas a la izquierda en grupos plegables (`Fold.tsx`, con «+» para añadir), lienzo en el centro (2D, «Ver en 3D» o los dos) con una sola barra arriba y la columna de herramientas a la izquierda (`Canvas.tsx`: seleccionar, lápiz, formas, nota, dividir color, calco; sus opciones flotan solo mientras se usan) e inspector según lo seleccionado (pieza, estampados, detalles, notas) o, sin nada seleccionado, la prenda (modelo, medidas y datos). En el editor el menú general se recoge a iconos (`AppLayout.tsx`). Deshacer/rehacer con `useHistory.ts` (Ctrl+Z, Ctrl+Mayús+Z), Ctrl+S guarda. `annotations.tsx`: cotas con las letras de la tabla de medidas de la ficha, escala, cuadrícula en cm y notas con flecha (`DesignData.callouts`). `colors.ts`: carta de colores con nombre y código; cada pieza puede guardar su nombre y código (p. ej. Pantone)
- Hoja de ruta del Diseñador (orden acordado y fases hechas): `docs/hoja-de-ruta.md`
- Detalles y fornituras (`src/designer/details.tsx`): cada detalle (botón, cremallera, ojete, remache, herrete, etiqueta, parche, bolsillo, trabilla, cordón, cinta, velcro, hebilla, costura decorativa, pinza, roto, deshilachado y desgaste; su forma ajustable —alto, esquinas, fondo, hilos, densidad…— en `Detail.shape` con los deslizadores de `SHAPE_PARAMS`; los bolsillos de parche que trae la prenda base van marcados con `Shape.pocket` y su pieza guarda su forma en `PieceStyle.shape` —fondo recto, en pico o redondo, pico, esquinas, alto—, que `reshapePockets` (`pocketShape.ts`) aplica al dibujar; sus estilos en `DETAIL_STYLES` y los alargados, con largo, en `LONG_DETAILS`, de `shared/designs.ts`) se describe como una lista de trazos (`Prim`) centrados en (0, 0), que se pintan en SVG (`PrimsView`) y en canvas (`drawPrims`). `DesignData.details` son los colocados a mano (pestaña Detalles, `DetailsPanel.tsx`); `DesignData.hardware` es el estilo de los botones y la cremallera de la prenda base, que el dibujo marca con `Shape.role` (`button`, `zip`). En 3D van en la imagen de estampados y en un mapa de relieve (`PrintLayer.relief`) que el material usa para dar volumen a bordados, parches y fornituras
- Ropa de mujer: cada diseño es de Hombre, Mujer o Unisex (`options.genero`, `genderOf`/`bodyKind` en `shared/designs.ts`; Unisex se patrona como hombre). Las tallas de mujer están en `measurements.ts` (`standardBody(talla, 'mujer')`, `clientBody(m, kind)`); las plantillas pasan `fem` a `drawTop`/`drawPants` (hombros más estrechos, cintura entallada, pinzas de pecho en camisas y chaquetas, cadera más marcada). Los tops de mujer (tirantes, palabra de honor, halter, cruzado, corsé) se dibujan en `femtop.ts`; los shorts son el pantalón corto con largo «mini». En «Nuevo diseño», `NEW_DESIGN_CATALOG` marca con `only` lo que es solo de un cuerpo
- Plantillas de la marca: un diseño con `DesignData.brandTemplate` sale en «Nuevo diseño» y se copia entero al usarlo
- Lookbook (`/disenador/lookbook`, `pages/designer/Lookbook.tsx`): se elige un outfit (arriba, debajo, pantalón, cabeza, calzado), el cuerpo, el escenario y las vistas, y la app da el texto para una IA de imágenes externa (`lookPrompt` en `src/designer/lookbook.ts`: prenda, corte, colores con nombre y código —`colorWords` pone nombre a los que no lo tienen—, tejidos, estampados con técnica y tamaño, fornituras y notas) y los dibujos técnicos de cada prenda como referencias (`exportFlat`). Las fotos que devuelva la IA se suben como «Fotos» de un proyecto y salen también en la ficha de su cliente (`ClientPhotos` en `ClientForm.tsx`)
- Probador (`/disenador/probador`, `pages/designer/Probador.tsx`): el maniquí, con las medidas de un cliente o las estándar, lleva a la vez una prenda de arriba y un pantalón ya diseñados. En la vista 3D del editor se ve solo la ropa, sin maniquí (`Scene showBody={false}`: se oculta el material del cuerpo, no la malla, porque la ropa necesita su esqueleto); «Llevar con…» añade otra prenda a la prenda abierta (se recuerda por diseño en el navegador). `useDesign3D` (`Design3D.tsx`) convierte un diseño en prenda 3D con sus estampados; `Scene`/`Mannequin` aceptan `outfit` (prendas que van debajo) y el pantalón con `Design.under` se ciñe a la cintura para quedar por dentro
- En 3D las prendas de arriba (sudadera, camiseta, polo, camisa, bomber, puffer, cazadora, cortavientos y el chaleco, sin mangas con `TopShape.sleeveless`) se cosen con patrón (`cloth/hoodie.ts`, el de la sudadera generalizado): `Design.top` (`TopShape`, lo rellena `topShapeOf` en `to3d.ts`) dice el bajo (canalé, dobladillo o pretina), los puños (canalé, dobladillo o puño de camisa), el cuello (tira de canalé tumbada; alto, ceñido u holgado según la opción «Ajuste del cuello alto» (`neckFit`, `neckHeight`); mao; o de camisa/polo con pie y pala doblada; todos se sujetan a su sitio con `collarPins`) y si es acolchada, con sus canales en relieve (`TopShape.quilt`, dibujados en el shader con `QUILT_GLSL` de `Garment.tsx` sobre el patrón plano, con las formas del Diseñador; los dibujados a mano aún no salen en 3D); la capucha sale con `Design.hood`. La manga larga acaba en la muñeca del maniquí (las manos siempre se ven; lo que el diseño la alargue por medidas se suma). Las prendas cosidas no reciben sombras sobre sí mismas (sus pliegues interiores las manchaban); sí las echan. En su lugar llevan sombra de pliegues calculada al coserlas (`clothOcclusion` en `dress.ts`, atributo `occlusion`: cuánta tela tiene delante cada punto), una ligera variación de tono del tejido (`FABRIC_GLSL` en `Garment.tsx`) y menos reflejo en las telas mate (`specularIntensity` según la rugosidad); donde la tela se ha recogido salen arruguitas más finas que la malla (`gathering` en `dress.ts`, atributo `wrinkle`, `fabricWrinkles` en el shader), y el relieve del tejido también oscurece su fondo. Las piezas en tubo (manga, puño) tienen rigidez a través de su costura (`Cloth.bendAcross`), así no se doblan justo ahí. Calidad alta (`Design.quality = 'alta'`, interruptor del Probador, encendido por defecto): malla un 30 % más fina en todas las piezas (`res` en `hoodie.ts`, `pants.ts`, `femtop.ts`) y dos pasadas por paso (`RelaxOptions.iterations`); el Probador la aplica de forma progresiva (primero la versión rápida y, cuando todas las prendas la tienen, se afina sola). El worker hace un encargo cada vez y descarta sin calcular los que han quedado viejos (cola en `dressClient.ts`). El hilo del tejido también se ve en el color (`uWeave`: lados claros y oscuros de cada hilo; en el denim, la trama blanca). Los pantalones también se cosen (`cloth/pants.ts`): delantero y trasero de cada pierna, costados, entrepierna, tiro y cinturilla; `Design.pants` (`PantsShape`: corte slim/regular/ancho/baggy, bajo recto/vuelto/puño y cintura, de `pantsShapeOf` en `to3d.ts`) y `legLength` para los cortos. Los largos llevan tela de más en el bajo que cae y se apila sobre las zapatillas: se asientan con suelo y con los pies «hinchados» como si llevaran zapatillas (`withShoes` en `dress.ts`). Las prendas puestas van por capas (`Design.layer`: pantalón, camiseta, prenda de arriba) y cada una se calcula después de las de patrón que tiene debajo (`Design.below`) y se asienta sobre su superficie (`DressInput.underlay`, `setUnderlay`/`useUnderlays`/`mergeUnderlays` en `dressClient.ts`); `outfitOf` (`Design3D.tsx`) arma el conjunto, y cada capa tiene su propio turno de cálculo. Cierre delantero (`TopShape.closure`: botones o cremallera, de arriba abajo o solo desde el escote, con tapeta): el delantero se parte por el centro (`PanelSpec.split` en `Cloth.ts`: la columna tiene un punto para cada lado; el borde `tapeta` dibuja sus pespuntes), cerrado se cose y abierto (`Design.open`, opción «Abierta» del editor 3D y del Probador, con «Debajo»: camiseta básica blanca o negra, `basicTee`) cada delantero cae a su lado; los botones (con sus agujeros e hilo) y la cremallera (dientes, cursor y tirador) son geometría de verdad (`addClosure` en `dress.ts`, zona `botones` y `ojales`), y en 3D no se pintan los del centro del dibujo. Bolsillos de parche, solapas, vivos de bolsillos de ojal, la vista del bolsillo lateral del pantalón y la banda lateral son parches (`cloth/patches.ts`: una forma en el patrón plano de una pieza que `addPatches` de `dress.ts` construye pegada a la tela asentada, con sus pespuntes y, si lleva, su botón); las trabillas son cajas (`Tab`); el pantalón también lleva cordón (los mismos de la capucha), botón y bragueta (borde `bragueta`), según `PantsShape` (`sidePockets`, `backPockets`, `cargo`, `cord`, `stripe`) y las chaquetas `TopShape.pockets`/`sleevePocket`. También el botón del puño de camisa, el bolsillo de pecho de parche (`TopShape.chestPocket`), la pretina recta de la cazadora (`flatBand`) y el puño estrecho de la manga corta. El top de mujer tiene su propio patrón (`cloth/femtop.ts`, `Design.femTop`: tirantes, palabra de honor, halter, cruzado o corsé, con su escote y tirantes finos o anchos). Solo quedan como tubos (`buildGarment` en `Garment.tsx`) las prendas sin patrón (p. ej. el vestido, que aún no tiene prenda base); con una prenda de arriba de tubo, el pantalón de debajo se recorta por lo que esta tapa (`coveredBy`)
- Medidas editables (`src/designer/measures.ts`): `DesignData.measures` guarda cm por punto de medida; la proporción con la medida que tocaría estira el dibujo (`DrawScale`, que reciben `drawTop`/`drawPants`), la prenda 3D (largo, manga y `chestScale`) y la tabla de la ficha técnica (la diferencia se suma a todas las tallas). Algunas medidas acompañan a otras (`FOLLOW`). Sin medidas propias, todo queda igual
- Estirar forma (`src/designer/handles.tsx`, herramienta de la columna del lienzo): puntos que se arrastran para cambiar una medida (escote: ancho y caída; alto del cuello, punta del cuello y alto de la capucha, que se estiran en `stretchCollar` de `top.ts`; pecho, largo, manga, puño; cadera, rodilla, bajo). Cada punto se encuentra solo: se dibuja la prenda con esa parte un 10 % mayor y se coge el punto que más se mueve, así vale para cualquier prenda base. Mientras se estira, el encuadre del dibujo se congela (`FlatView.lockFrame`)
- Dibujo a mano y calco (`src/designer/drawings.tsx`): `DesignData.drawings` (lápiz, línea, rectángulo, elipse) y `DesignData.tracings` (boceto para calcar, uno por vista). Estampados, trazos, notas y calcos pueden estar ocultos (`hidden`) o bloqueados (`locked`). Los estampados se ajustan solos al centro y, con la cuadrícula, a cada cm
- Variantes de color (`src/designer/colorways.ts`): la activa vive siempre en `DesignData.pieces` y el resto en `DesignData.colorways`, así el dibujo, la vista 3D y la ficha técnica usan la activa sin saber de variantes
- Exportar (`src/designer/exportFlat.tsx`, botón «Exportar» del editor en `pages/designer/ExportMenu.tsx`): pinta las vistas fuera de la pantalla sin las ayudas del editor y las junta en un SVG con imágenes y fuentes dentro (`embeddedFontCss` y `toDataUrl` de `fonts.ts`); de ahí sale el PNG (≈3600 px) y el PDF A4 (`pdf.ts`, escrito a mano, sin librerías)
- Superficies y bloques de color (`src/designer/surfaces.ts`): cada pieza puede llevar una superficie (`PieceStyle.surface`: rayas, cuadros, lunares, camuflaje, tie-dye, logo repetido, degradado) y un lavado (`PieceStyle.wash`), que se pintan en un azulejo (`pieceTile`): es el relleno del dibujo y la textura de la tela en 3D (`SlotStyle.tile`). `DesignData.blocks` divide una pieza con una línea (`halfPlane`, recortado a la pieza); en 3D salen los del cuerpo (en `printLayers.ts`)
- Materiales del Diseñador: `src/designer/materials.ts` es el catálogo integrado de tejidos y fornituras (ids `cat:…`), con su textura 2D (`weave`), brillo (`gloss`) y aspecto 3D (`look`). Añadir un material = una entrada en `CATALOG`. `swatches.tsx` dibuja las texturas en SVG (muestras y plano) y `pages/designer/MaterialPicker.tsx` es el selector con muestras (catálogo + materiales propios de la Biblioteca). Un material de la Biblioteca puede llevar textura (`Material.look`, un id `cat:…` del catálogo, elegido en su ficha): con ella se ve así en el dibujo y en 3D. Cada cuenta nueva empieza con tejidos, fornituras, hilo y etiquetas básicos (`BASIC_MATERIALS` en `shared/library.ts`, con su textura; los crea `addBasicMaterials` de `worker/library.ts` al registrarse) y en la Biblioteca «Añadir básicos» añade los que falten (`POST /api/materials/basicos`). Si una pieza no tiene material, se ve con el de por defecto de su prenda base (`defaultMaterialFor`)
- 2D ↔ 3D: el editor tiene vista 2D, 3D o ambas (`pages/designer/Design3D.tsx`). `src/designer/to3d.ts` traduce el diseño a la prenda 3D (prenda, corte, largos, detalles y color/material de cada pieza → zonas `GARMENT_SLOTS` de `src/types.ts`); el maniquí toma las medidas del cliente del diseño si las tiene (si no, 180 cm y 80 kg de hombre o 165 cm y 60 kg de mujer, `DEFAULT_MEASUREMENTS`/`FEMALE_MEASUREMENTS` en `to3d.ts`)
- Estampados: `src/designer/prints.tsx` dibuja los estampados (gráficos o textos) sobre el flat y `Transformable` permite moverlos, escalarlos y girarlos (también se usa en el creador). `printZones` de cada plantilla son las posiciones rápidas. 1 unidad del lienzo ≈ 0,5 cm (`UNITS_PER_CM`)
- Gráficos: `src/pages/library/Artworks.tsx` (lista y subida) y `ArtworkCreator.tsx` (creador de logos por capas, `artLayers.tsx`). El creador tiene deshacer/rehacer (`useHistory`), atajos (flechas, Ctrl+D/G/A, Supr), selección múltiple con Mayús y grupos (`ArtLayerMeta.group`), capas ocultas o bloqueadas (las ocultas no se exportan) y ordenables arrastrando, guías que pegan el centro y los bordes al lienzo y a las otras capas, alinear y repartir, y zoom (Ctrl + rueda). Los textos del creador se reparten letra a letra (`layoutText` en `artLayers.tsx`): varias líneas con alineación e interlineado, formas (`TEXT_WARPS`: arco, círculo, onda, bandera, abombado, perspectiva, vertical), degradado, dos contornos y sombra con desenfoque (y relleno con una imagen, `fillImage`). Formas (`SHAPE_KINDS`: rectángulo con esquinas, círculo, estrella, polígono, línea, flecha, corazón, escudo, banderola, sello, estallido, laurel) y trazos de la pluma y el lápiz (capas `path` con `PathNode`) en `artShapes.tsx`, con relleno liso, degradado o textura (`FillStyle`, `FillDefs`); al guardar se exporta un SVG a Workers KV. Plantillas de logo (escudo college, sello, badge vintage, número varsity, monograma, streetwear) en `artTemplates.ts`: capas listas para editar pintadas con los dos primeros colores de la marca; añadir una = una entrada en `LOGO_TEMPLATES`. Los colores del creador (`ColorField`) muestran primero los de la marca y abren la carta de colores del Diseñador. Producción (`ProductionPanel.tsx` y `artProduction.ts`): ancho real en cm, tintas o hilos con su nombre y código, puntadas orientativas de bordado (`STITCHES_PER_CM2` × superficie con tinta), avisos según la técnica, prueba en una prenda (`FlatView` con el gráfico al ancho real; los estampados aceptan una URL local en `file`) y exportación a tamaño real (PNG con sus ppp en el bloque pHYs, SVG en cm). Las imágenes tienen «Quitar fondo» (`removeBackground`: borra el color del borde, o ese color en todas partes). Las imágenes de gráficos no se borran al editar o eliminar el gráfico, porque los diseños guardan su propia referencia. Al exportar, las fuentes de Google usadas se incrustan en el SVG (solo sus letras, en base64), así se ve igual en cualquier sitio (por eso la CSP de `files.ts` permite `font-src data:`)
- Tipografías (`src/designer/fonts.ts`): catálogo de Google Fonts por estilos más las del sistema; en los diseños se guarda la pila CSS (`'Anton', sans-serif`). `loadFont` las descarga al usarlas, `loadFontPreviews` una muestra ligera para el selector (`src/components/FontPicker.tsx`) y `useFontsVersion` repinta al llegar. Efectos del texto en `Print` (arco, vertical, espaciado, contorno, sombra, cursiva) y su reparto en `textLayout` (`prints.tsx`), el mismo en SVG y en el canvas del 3D
- `src/components/ui.tsx` — piezas comunes (cabecera de página, campos, precio, estados de carga)
- `src/api/client.ts` — llamadas a la API, `useApi` para cargar datos y subida de imágenes (se reducen antes de subirlas)
- `src/shared/` — tipos compartidos por la web y la API (`clients.ts` con la lista de medidas, `library.ts` con categorías y unidades de precio)
- `worker/` — API: `index.ts` (rutas y acceso), `auth.ts` (registro, login, sesiones y perfil), `clients.ts`, `library.ts` (materiales y proveedores), `designs.ts` (diseños), `artworks.ts` (gráficos), `projects.ts` (proyectos, colecciones y tareas), `production.ts` (fichas técnicas y órdenes de fabricación), `economy.ts` (gastos generales y resumen económico), `files.ts` (imágenes en Workers KV), `http.ts` (utilidades)

La capucha puede ir puesta (`hoodUp`) o bajada (cae por la espalda como una bolsa: las costuras central y de arriba van por el centro), cruzada (`hoodCross`) y con el cuello alto cosido por dentro (`hoodCollar`), y lleva cordones con ojales y herretes (`addCords` en `cloth/dress.ts`; las chaquetas sin cordones propios ganan la opción en `withNeckExtras`)

## Convenciones

- Interfaz y textos para el usuario **en español**. Nombres de código (variables, funciones, tipos) en inglés; comentarios en español.
- Medidas que ve el usuario en **centímetros**; en la escena 3D todo en **metros** (1 unidad = 1 m), con el suelo en `y = 0`. El maniquí y su ropa trabajan internamente en las unidades del modelo (cm) y se escalan a metros en `Avatar.tsx`.
- Componentes funcionales con hooks, sin librerías de estado global mientras no haga falta.
- Las prendas se derivan del cuerpo del maniquí (articulaciones y alturas de `ModelInfo`); no metas tamaños fijos en los componentes 3D.
- Añadir una tela = una entrada en `FABRICS`. Añadir una prenda = un caso en `GarmentType` y en `buildGarment` (`Garment.tsx`).
- Los modelos 3D van como `.glb` ligeros (Cloudflare no admite archivos de más de 25 MB); nunca subas el `.fbx` original.

## Cómo trabajamos los dos (importante)

- **Trabajamos directamente en `main`**, sin ramas ni Pull Requests, para que nadie tenga que fusionar lo del otro.
- Antes de empezar cada cambio: `git pull` para partir de lo último del otro.
- Commits pequeños y con mensaje claro en español (p. ej. `Añade prenda falda`).
- Al terminar cada cambio: `npm run build` (si falla, no se sube), `git pull --rebase` y `git push`. Al subir a `main`, Cloudflare despliega a producción.
- Si al traer los cambios del otro hay conflictos, resolverlos en local antes de subir; nunca `git push --force`.
- Repartirse las zonas para no tocar los mismos archivos a la vez; si hay que cambiar algo compartido (`types.ts`, `body.ts`), avisar al otro.

## Cloudflare y secretos

- La configuración pública va en `wrangler.jsonc` (sí se sube).
- Los secretos (API keys, tokens) **nunca** van en el repo: en local en `.dev.vars` (está en `.gitignore`) y en producción con `npx wrangler secret put NOMBRE` o desde el panel de Cloudflare.
- D1 guarda los datos y Workers KV (binding `FILES`) las imágenes; ver README para crearlos en producción. Al quitar o cambiar una foto, la API borra la anterior de KV.

## Cuentas y datos por usuario (importante)

- Todas las rutas de la API menos `/api/auth/*` exigen sesión (`currentUser` en `worker/auth.ts`). Cada handler recibe el `uid` de la cuenta.
- **Toda tabla nueva con datos de usuario lleva `user_id`**, y toda consulta filtra por él (`WHERE ... AND user_id = ?`), también los `UPDATE` y `DELETE`. Las tablas hijas (p. ej. las partes de un proyecto) cuelgan de su padre y se comprueba antes que el padre es de la cuenta.
- Las referencias que llegan del navegador (cliente, proyecto, material, proveedor, colección) se validan con `ownedRef` (`worker/http.ts`) antes de guardarlas.
- Los archivos de KV guardan en sus metadatos la cuenta que los subió; solo esa cuenta puede verlos o borrarlos.
- Contraseñas con PBKDF2 (Web Crypto). La sesión es una cookie `HttpOnly` con un token aleatorio; en D1 solo se guarda su hash. Las peticiones que cambian datos desde otro origen se rechazan.
